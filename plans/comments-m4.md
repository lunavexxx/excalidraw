日期：2026-10-12。状态：评论功能已在本地实现，自动化与隔离服务联调回归通过；浏览器视觉验收受电脑控制连接故障阻塞，尚未部署。

本计划细化 `collab-platform.md` 的 M4。用户已认可评论权限、图钉定位、管理规则、通知与已读的建议，并明确本次加入表情反应及 emoji 支持。沿用已有画布权限、持久通知、个人提醒连接和 `collaboration_outbox`，不重新建设邀请或申请访问链路。

## 1. 本次交付范围

- 在线画布创建评论线程：可在空白位置放置，也可绑定单个元素。
- 画布头像图钉、点击展开线程、侧栏与图钉双向定位。
- 留言、回复、@提及、作者编辑/删除留言。
- 线程解决、重开、管理者删除整个线程。
- 留言的 emoji 反应：添加、取消、计数和参与者展示。
- 正文完整 Unicode emoji 输入、粘贴、显示，以及 emoji 选择器插入。
- 搜索正文和作者；按最近活动或未读优先排序；已解决筛选。
- 按用户保存线程已读进度，侧栏未读提示和全部已读。
- 评论定位链接、@提及/回复/解决状态的站内通知跳转。
- 同画布实时更新、重连补拉、请求失败保留草稿、移动端适配。

附件、图片上传、Markdown/富文本、自定义图片表情、邮件/短信通知和嵌套多级回复不在本次范围。emoji 和表情反应属于本次正式功能。

本地未保存草稿提示先保存为在线画布，再创建评论；本轮不建立第二套本地评论存储或迁移协议。

## 2. 权限与状态规则

| 操作                                 | 权限                                                     |
| ------------------------------------ | -------------------------------------------------------- |
| 阅读评论、搜索、打开定位链接         | 有画布读取权限，包括有效分享链接的匿名访客               |
| 创建线程、回复、@提及、添加/取消反应 | 有画布读取权限的真实登录账号，包括 viewer                |
| 编辑、删除单条留言                   | 留言作者；画布管理者也可删除留言，但不能冒用作者编辑正文 |
| 解决、重开线程                       | 线程发起者、画布 owner、所属工作区 owner/admin           |
| 删除整个线程                         | 画布 owner、所属工作区 owner/admin                       |
| 移动评论图钉、调整绑定               | 线程发起者或画布管理者                                   |

匿名访客只读，即使持 editor 分享链接也不能发表评论或反应。已有真实登录账号但只依赖 guest 票据读取画布时，同样需要账号获得画布授权后才能评论。前端展示提示，后端强制校验；不能仅检查当前 JWT 是否存在。

- 解决后的线程仍可阅读和查看反应；继续回复前须由有权限者明确重开。解决不删除内容，默认在图钉和列表中隐藏。
- 删除单条留言保留占位、作者和时间，隐藏正文、提及和反应。首条留言删除后，已有回复和线程仍保留。
- 删除整个线程采用软删除，图钉、侧栏和新查询隐藏；旧链接显示“评论已删除”，不得显示残留正文。
- 失去画布访问权限后不能通过线程 ID、评论链接或通知读取正文；身份和权限在每次操作时重新检查。
- 评论不参与画布元素撤销/重做，也不写入画布元素数组、场景快照或图片导出。

## 3. 图钉、编辑器和侧栏交互

### 图钉与定位

- 增加评论模式入口，沿用参考图的底部入口，并可从评论侧栏进入。Esc 退出，放置图钉不会意外绘制或移动元素。
- 点击空白位置保存画布坐标；点击元素时记录 element_id 和元素局部锚点。缩放、平移、旋转、移动和调整元素尺寸后正确重新投影图钉。
- 图钉绑定一个元素，首版不绑定多选集合；组合操作保留对原 element_id 的绑定。
- 元素删除后保留线程，以最后已知的位置展示并标注“关联元素已删除”；元素恢复时可以恢复定位。定位不能在元素消失时跳回最初创建位置。
- 复制元素、复制画布、导出或导入场景不会复制原画布的评论。评论属于在线画布的独立业务数据。
- 图钉显示发起者头像，回复参与者可用叠放头像表达；无头像使用昵称首字母。选中、未读、已解决状态清楚可辨。
- 图钉保持固定屏幕尺寸，画布坐标随视口转换；密集图钉避免遮挡主要操作，浮层靠边时自动选择可见方向。

### 线程与输入

- 点击图钉打开就地浮层；点击侧栏线程定位画布并打开同一线程，当前项高亮。一次只激活一个线程。
- 浮层包含作者、时间、正文、反应、回复和线程操作。长线程内部滚动，输入区始终可用。
- Enter 发送、Shift+Enter 换行；中文输入法组合输入期间不触发发送。空白正文不能发送，emoji-only 留言允许发送。
- 留言正文按纯文本保存和显示，不执行 HTML。正文中的 emoji 不转成图片或远程资源。
- @输入显示有画布权限的成员候选，支持姓名搜索和键盘选择；仅插入姓名文字不视作真实提及，持久化 user_id 与正文位置。
- 编辑留言时重新校验提及；仅对新加入的被提及者生成提醒，避免重复通知原提及者。
- 请求失败保留当前内容并显示可重试错误，发送期间避免重复提交。切换画布时按画布/线程隔离草稿，不能串到另一画布。

### 侧栏与移动端

- comments 页签提供搜索、排序、显示已解决和全部已读；默认最近活动排序、隐藏已解决。
- 搜索覆盖根留言与回复，结果展示所属线程；分页加载不能把第一页当作评论总数或未读总数。
- 侧栏搜索与未读排序基于服务端结果，已解决筛选同时作用于侧栏和画布图钉。
- 移动端以可用的线程面板呈现，确保软键盘出现后仍能看到输入区与发送按钮。
- 图标按钮有可访问名称；图钉和反应支持键盘操作、焦点指示和触控。打开/关闭浮层管理焦点，点击外部关闭不丢失草稿。
- 新 DOM/browser API 使用 app.ownerDocument / app.ownerWindow；没有 app 时从挂载节点派生，不增加全局 document/window 依赖。
- 覆盖已有 TypeScript 类型字段时优先使用 `Merge<Base, Overrides>`，遵守仓库 AGENTS.md。

## 4. 表情反应与 emoji

### 正文 emoji

- 支持系统输入法、粘贴和内置选择器插入 Unicode emoji，包括肤色修饰、组合家庭、旗帜和 ZWJ 序列。
- 同一个选择器可以用于正文和反应。首版提供常用分类、名称搜索和最近使用；系统输入及粘贴的支持不受选择器常用列表限制。
- 插入位置为文本光标/选区，插入后保留输入焦点和草稿；不得每次追加到正文末尾。
- 使用系统 emoji 字体回退，浅色/深色主题可读，不依赖外部 CDN 或图片表情下载。
- 长度限制不拆开 emoji 组合或代理对；正文允许最多 5,000 个 Unicode 字符，同时限制总请求字节数。

### 留言反应

- 每条未删除留言都能添加反应，根留言和回复一致；同一用户对同一留言的同一 emoji 最多一条。
- 反应采用明确的添加/删除接口，重复请求幂等；不使用可能被重试反向执行的 toggle 接口。
- 用户可添加多种不同反应；再次点击自己的反应取消。界面显示 emoji、计数和自己的选中状态，展开可查看参与者公开昵称。
- 默认快捷表情包含 👍 ❤️ 😂 🎉 👀 🙏，选择器可选其他合法 emoji；服务端拒绝普通文字或多个独立 emoji 冒充单个反应。
- 组合序列和肤色修饰按完整 emoji 保存、校验和比较；统一处理等价表现，避免视觉相同的重复计数。
- 反应增减向同画布实时广播，但不逐条产生站内通知，避免刷屏；反应本身不使线程重新变为未读。
- 每个用户每条留言至多 20 种反应，写接口有限频和数量保护；不信任客户端计数或参与者身份。

## 5. 通知与已读

- 新建线程仅通知明确 @提及者，不通知整个画布的所有成员。
- 新回复通知线程发起者、已有回复作者和本次 @提及者；同一账号仅一条，排除操作者。
- 解决/重开通知线程参与者，排除操作者；反应、普通编辑和单条删除只更新界面，不新增通知。
- 收件人必须仍有画布权限；提及目标也须有权限，不允许借 @向无权限账号授予访问。
- 通知记录引用线程，点击进入对应画布并定位评论；线程删除或权限撤销时显示实际状态，不能依赖通知文本推断可访问性。
- 线程未读进度与站内通知 read_at 分别存储。仅打开侧栏不把所有线程标为已读；打开具体线程并加载内容后标记读到已展示的版本。
- 新线程、新回复和重开推进线程的 unread_version；反应、编辑、删除、解决推进内容 version，但不额外制造未读。
- 已读提交携带客户端已展示的 unread_version，防止同时到达的新回复被顺带标为已读。多标签页和多个设备最终一致。
- “全部已读”仅作用于当前画布、服务端读取时已存在的线程版本；不得误清其他画布或之后到达的回复。
- 每次已读仅清理该用户对应线程、已展示范围内的评论通知；铃铛中的全部已读不代表用户已实际阅读全部线程。

## 6. 数据与 API 契约

采用独立迁移 `0007_comments`，保留原始 schema 草稿作为历史记录，以下结构以实际 canvas 模型为准。

| 表                   | 主要职责                                                                             |
| -------------------- | ------------------------------------------------------------------------------------ |
| comment_threads      | canvas_id、created_by、锚点、位置回退、解决/删除状态、version、unread_version、时间  |
| comments             | thread_id、author_id、纯文本 body、客户端幂等标识、created_at、edited_at、deleted_at |
| comment_mentions     | comment_id、user_id、每次提及的 UTF-16 正文范围；通知按收件人去重                    |
| comment_reactions    | comment_id、user_id、emoji、created_at；三字段唯一约束                               |
| comment_thread_reads | thread_id、user_id、last_read_version、read_at；只允许已读进度前进                   |

画布、线程、留言外键与查询索引覆盖活跃线程、时间排序、未读、留言分页和反应汇总。删除与迁移回退须显式清理相关记录，不破坏既有通知表或 outbox。

沿用 HTTP 200 + code 的业务响应，不另建响应风格。资源 ID 必须同时限定在路径中的 canvas_id/thread_id 下查询，不能只凭单个留言 ID 写入。

拟议接口：

- GET/POST `/canvases/:id/comment-threads`：列表与创建；列表支持 search、sort、resolved、游标，返回全局统计与分页结果。
- GET `/canvases/:id/comment-pins`：轻量图钉与版本数据，不为每个图钉拉完整回复。
- GET/PATCH/DELETE `/canvases/:id/comment-threads/:threadId`：详情、锚点/解决状态更新、管理者删除。
- POST `/canvases/:id/comment-threads/:threadId/comments`：回复。
- PATCH/DELETE `/canvases/:id/comment-threads/:threadId/comments/:commentId`：作者编辑/删除。
- PUT/DELETE `/canvases/:id/comment-threads/:threadId/comments/:commentId/reactions`：添加/取消一个 emoji。
- POST `/canvases/:id/comment-threads/:threadId/read`：提交已展示版本。
- POST `/canvases/:id/comment-threads/read-all`：当前画布全部已读。
- GET `/canvases/:id/comment-mention-candidates`：公开成员字段，姓名搜索和分页；不返回手机号等管理字段。

创建、回复支持客户端 request_id，数据库约束保证重试不新增留言或重复通知。编辑、解决和锚点修改携带预期 version；冲突返回 43002，客户端补拉当前版本，避免覆盖其他人的修改。反应操作基于唯一约束幂等。

服务端在事务中校验权限和资源状态，锁定线程、写入留言/状态/反应、递增版本，并写入必要通知和 outbox。回复与解决并发时具有明确顺序，不能出现已解决线程接纳新回复、却仍标为解决的结果。

## 7. 实时与恢复

- 评论写操作走 HTTP API，持久化提交成功后才显示已发送；不通过画布元素同步通道写评论。
- `collaboration_outbox` 增加评论事件类型和必要的线程/版本引用。room 消费必须读取并区分 type，不能把评论事件误当作权限变化。
- `comments-changed` 是独立的画布事件；`comment-reads-changed` 是个人已读提示；已有 `notifications-changed` 继续驱动铃铛。
- 所有 room 实例都能消费同一业务事件并向各自已授权连接投递；不能使用共享消费组分摊后导致其他实例收不到。
- 画布事件只发送 canvas_id、thread_id 和版本提示，正文通过重新鉴权的 API 获取；不允许客户端自报作者或收件人。
- 收到变化按线程合并刷新，丢弃旧画布响应和旧版本结果；未展开的线程只刷新列表/图钉摘要。
- 重连、切换画布和重新获得页面焦点补拉最终状态。实时事件是提示，数据库是事实来源；不依赖事件从不丢失或严格按到达时间排序。
- 核查现有 outbox 高水位消费在并发事务提交下的漏事件风险，使用可重读并去重的交付方式或周期版本补拉兜底，不能直接把序列号大小等同于提交顺序。
- 请求断线时保留草稿；本轮不承诺离线自动发送。恢复后用户可重试，同一 request_id 仍只产生一次业务结果。

## 9. 必须通过的验收

1. A 创建图钉，B 实时看到并回复，A 解决，双方一致；重开后可继续回复。
2. 登录 viewer 能评论及反应但不能编辑画布；匿名 guest 能读、不能写；移除授权后无法通过旧线程地址继续读取。
3. 作者只能编辑自己的留言；线程发起者和管理者的解决权限、管理者删除权限正确，跨画布 ID 操作失败。
4. @只产生合法账号通知；回复收件人去重、排除自己；离线后通知仍可补拉并定位正确线程。
5. 缩放、平移、旋转、移动/缩放元素后图钉位置正确；元素删除后保留最后位置；复制/导出不复制评论。
6. emoji-only、中文加 emoji、肤色、家庭组合、旗帜完整存储显示；光标中间插入不破坏文字；输入法 Enter 不误发送。
7. 两人并发添加同一种反应得到计数 2；重试不会重复，取消只移除自己的反应；不会生成多余通知或未读。
8. 查看线程同时收到新回复，新回复仍未读；两个标签页读取状态收敛；当前画布全部已读不清其他画布。
9. 重复/乱序实时提示、断线重连、room 重启后恢复数据库最终状态；发送失败保留草稿，重试不重复。
10. 长列表/长线程分页、搜索回复、显示已解决与未读排序正确；深浅色、移动端及键盘操作可用。
