# 多人协作：分享、邀请、申请与成员可见性

日期：2026-10-08。状态：待实施，基于当前代码检查，尚未进行运行验收。

本计划细化 `collab-platform.md` 的 M2/M3，并将 M4 的站内通知提前作为公共能力。目标是让用户通过主动授权、邀请链接、分享链接和申请审批进入协作，同时看清谁有权限、谁正在在线。

## 1. 当前实现与缺口

| 能力 | 当前实现 | 本轮补齐 |
|---|---|---|
| 主动授权 | owner 按手机号添加已注册用户，editor/viewer 两级 | 所属工作区 owner/admin 也可管理；明确直接添加与待接受邀请的区别 |
| 授权名单 | 仅查询 canvas_collaborators，且仅 owner 可读 | 汇总画布 owner、工作区继承权限、直接授权，展示实际权限与来源 |
| 分享链接 | editor/viewer、过期、撤销；明文 token 只返回一次 | 稳定管理入口、清楚说明链接权限、创建后复制与后续重新生成路径 |
| 实时在线 | UserList 已位于右上角，room 广播 socket ID | 自动加入、账号身份和头像、多个标签页合并、在线与授权名单关联 |
| 协作中的分享 | ActiveRoomDialog 替代分享管理界面 | 开始协作前后使用同一分享管理界面 |
| 权限变化 | HTTP 会重新鉴权；room 入房后保存角色 | 已连接用户降级、移除、链接过期/撤销及时生效 |
| 邀请 | 现有“邀请”实际为直接授权，目标必须已注册 | 可登录/注册后接受的定向邀请链接、待接受/过期/撤销状态 |
| 申请访问 | 无 | 申请入口、待审批列表、批准/拒绝/撤回及结果反馈 |
| 通知 | 无持久化通知模型 | 邀请、申请、审批结果共用的站内通知与未读提示 |

已有 canvas_events 保存的是画布元素更新，不是用户通知，不复用为通知表。

## 2. 产品规则与权限

### 2.1 管理能力

- 画布 owner、所属工作区 owner/admin 可以管理分享、直接授权、邀请和审批。
- 使用独立能力字段，例如 can_manage_collaborators、can_manage_share_links、can_review_requests；不把工作区 admin 映射成画布 owner。
- 编辑者可以编辑和复制普通画布地址；观看者只能查看。两者均不能授予权限或审批。
- 已获授权的登录用户可以查看成员展示名单；手机号等管理字段仅向管理者返回。匿名 guest 只展示当前在线用户的公开信息，不开放完整授权名单。
- 画布改名、删除和转移所有权不随本次分享管理权限扩展。
- 管理员定义沿用已有 workspace admin，本轮不引入画布级 admin。

### 2.2 有效权限与名单

- 延续现有最高权限合并规则：画布 owner > 编辑权限 > 查看权限；来源包括工作区成员与画布直接授权。
- 每人一条展示记录，附 effective_role、direct_role、workspace_role、权限来源和管理能力标识；owner 始终在名单内。
- 在名单中说明“来自工作区”。移除直接授权不等于移除继承权限；直接设置 viewer 也不能覆盖工作区 editor。操作结果必须显示实际权限，避免误导。
- 工作区管理员对成员的内容角色是 editor，界面可同时显示“工作区管理员”，不新增一套内容角色。
- 待接受邀请单列，不计入已授权人数。分享链接本身不是一个成员；匿名访问者出现于在线名单。
- 名单分页并支持查找；在线人数独立显示，不能把当前已加载的一页当作成员总数。

### 2.3 分享与邀请

- 普通画布地址只定位画布，不授予新权限；复制时说明“已有权限的人可访问”。
- 访问分享链接沿用现有 guest 模型，默认 viewer；可选择 editor、设置有效期、撤销。
- 不改变现有 guest 通过 room 编辑而 HTTP 写接口受限的边界，但应通过端到端测试验证编辑分享链接的实际效果。
- 主动添加：按手机号给已注册用户直接授权，立即生效；收到“已被添加到画布”通知，无需确认。
- 定向邀请：按手机号创建 invitation，复制邀请链接给对方。对方登录或注册后，服务器校验账号手机号匹配，接受后才写入授权。
- 未注册目标不直接报“无法邀请”，转为待接受邀请；本轮由用户复制链接发送，不增加短信或邮件投递服务。
- 邀请链接绑定目标和角色、限时有效、可撤销；只保存 token 摘要。手机号沿用现有加密/哈希能力，避免增加明文存储。
- 接受邀请幂等；已通过其他途径获得更高权限时不降级。已接受邀请的角色变更应走成员管理，不复用旧 token。
- 现有分享 token 无法从摘要恢复：管理列表不提供假“复制”；保留创建时复制，后续提供生成新链接，并明确旧链接是否继续有效。默认生成新链接不会自动撤销其他链接。

### 2.4 申请访问

- viewer 可在分享面板申请升级为 editor；无权限用户通过管理者生成的“申请访问链接”申请 viewer/editor。
- 申请访问链接只允许发现最少的申请入口信息，不授予画布读取权限；复用分享面板创建入口，使用独立用途的 token，不混用可读分享 token。
- 普通 /c/:id 无权限页提供登录、切换账号及说明；没有有效申请入口凭证时不开放可枚举的画布申请接口。保留现有不存在/无权限统一响应。
- 未登录者先登录，保留目标和入口凭证；guest 申请时也需绑定真实登录账号。
- 申请包含目标角色和可选理由；同一用户同一画布最多一条 pending。重复提交返回现有申请，不重复通知。
- 状态：pending / approved / rejected / cancelled。批准时可选择最终授予 viewer/editor，拒绝可附理由；用户可撤回。
- 批准事务内完成状态变更、授权写入和通知记录；审批者在操作时重新校验管理权限。
- 多个管理员并发审批只有一次成功；已批准、撤回或已获得足够权限的申请不能继续重复授权。
- 被直接添加后，匹配的 pending 申请应自动结案并通知；不足所申请角色时仍保持 pending。
- 审批中心展示申请人、画布、角色、理由、时间与状态，通知跳转到业务实体，不依靠通知文本决定状态。
- 入口撤销/过期、画布删除后不能新提交；待审批记录处理时重新检查画布有效性。拒绝后的再次申请应有冷却及限频。

## 3. 界面入口

| 入口 | 展示与动作 |
|---|---|
| 画布右上角 | 复用 UserList 显示在线头像、在线人数；溢出展开；管理者可从这里打开邀请入口 |
| 分享按钮 | 常驻入口，统一展示已授权人员、待接受邀请、链接与待审批数量；协作开始后仍可管理 |
| 授权成员列表 | 昵称、头像/首字母、实际角色、权限来源、在线状态；管理者可操作直接授权 |
| 在线列表 | 按账号合并 socket；自己可见，多标签页在线但只算一人；匿名访客单独展示 |
| 文件列表 | 接入现有 shared 列表能力，提供“与我共享”；邀请/审批通知可跳转到对应画布 |
| 邀请落地页 | 登录/注册 → 校验目标身份 → 接受 → 打开画布；覆盖账号不匹配、过期、撤销 |
| 无权限页 / viewer 分享面板 | 有效入口下申请访问；viewer 申请编辑；显示自己的申请状态 |
| 站内通知入口 | 未读数、通知列表、全部已读；管理者审批入口与申请者结果入口 |

授权数据来自 API，在线状态来自 room；没有在线信息时显示“连接中/状态暂不可用”，不要推断为离线。断网、重连、切换画布时清理旧状态。

presence 以服务端已验签账号身份为准，增加 user_id、公开昵称、头像、实际角色，避免将客户端自报身份作为授权依据。按用户聚合在线展示，光标和跟随仍保留 socket 维度，跟随时选择该账号的有效连接。

## 4. 数据、接口与事件

以下为拟议契约，实施时沿用现有 HTTP 200 + code 响应约定。

### 数据

- 沿用 canvas_collaborators、workspace_members、share_links；授权名单通过查询聚合，不复制工作区成员到画布授权表。
- canvas_invitations：画布、目标手机号加密值/哈希、角色、邀请者、token_hash、状态、有效期、接受账号与时间。
- canvas_access_entries：申请入口 token_hash、画布、创建者、有效期、撤销时间；不能换取 guest 读取票据。
- canvas_access_requests：画布、申请人、目标角色、理由、状态、审批者、最终授予角色、结果理由及时间。部分唯一索引限制 pending。
- notifications：recipient_id、type、actor_id、业务实体引用、read_at、created_at、去重键；按用户游标分页。
- transaction outbox：授权/邀请/审批事务写入通知与待投递事件，后台重试投递；实时推送只做提示，重新拉取数据库恢复最终状态。

### 接口

- 扩展画布详情返回能力；新增 GET /canvases/:id/members 展示有效授权名单，保留直接授权管理接口。
- 协作者及分享链接写接口改用管理能力鉴权；成员展示读接口与管理读接口分别控制返回字段。
- POST/GET /canvases/:id/invitations，撤销 invitation，邀请凭证预览与接受接口。
- POST/GET/DELETE /canvases/:id/access-entries：申请入口创建、管理、撤销。
- 带入口凭证提交无权限申请；有读取权限的 viewer 可直接提交升级申请。
- GET /canvases/:id/access-requests：管理者列表；本人查询、撤回及管理者批准/拒绝接口。
- GET /notifications、GET /notifications/unread-count、单条/全部已读接口。
- 现有 shared 画布列表接入前端；邀请接受和审批通过后可刷新列表。

### 实时事件

- canvas-members-changed：刷新授权名单与能力。
- canvas-access-changed：room 重新鉴权，降级只读或移除连接，同时更新客户端能力。
- presence roster：携带服务端身份的在线状态。
- notification-created / notifications-changed：个人频道，仅登录用户能加入自己的频道。
- user 个人频道独立于画布房间，无权限申请者也能收到结果；离线期间消息保存在 API 数据库。
- API 事务提交后的事件通过 outbox 和已有 Redis 基础设施投递给所有 room 实例；room 还需有限间隔复核权限与 token 过期，覆盖漏事件和链接自然过期。
- 权限更新设定可验证上界：正常事件推送后目标 2 秒内；故障恢复兜底不超过 30 秒。实现时不得依赖现有只在入房读取的 ACL 缓存；撤销收到后应先停用旧写权限再处理后续广播。

## 5. 实施顺序与交付批次

### A — 权限能力与完整授权名单

1. 抽出服务端管理能力判定，覆盖画布 owner、工作区 owner/admin 和 guest 的矩阵。
2. 提供包含权限来源的 members 查询和分页；扩展画布详情能力，区分展示与管理字段。
3. 分享界面合并会话状态与成员管理，支持直接添加、变更、移除及分享链接管理。
4. 接入“与我共享”文件入口，处理继承权限无法通过直接授权降级的提示。

交付：管理者可完成主动授权，所有已授权账号能看到完整名单；协作中分享入口可用。

### B — 在线身份、自动加入与动态权限

1. 所有具备内容权限的用户打开服务端画布后自动加入房间，复用现有同步/持久化流程，避免独立 saver 与 room 双写。
2. 连接前保留未同步修改，连接成功后切换持久化责任；断线草稿、重连补拉与画布切换沿用并核验现有版本/游标协议。
3. room 提供可信 presence 身份，UserList 关联成员，按账号聚合标签页。
4. 贯通权限变更投递、room 重鉴权、前端只读/失去访问反馈，覆盖多实例、撤销和自然过期。

交付：打开即在线协作；已授权与当前在线可同时查看；权限变更在现有连接生效。

### C — 通知底座与完整邀请

1. 新建通知、outbox、用户频道与通知界面，离线通知可补拉。
2. 主动添加生成通知；新增定向邀请模型、列表、撤销、邀请落地页与接受事务。
3. 覆盖未注册用户登录/注册后的返回路径、手机号不匹配与重复接受。

交付：既能直接添加已注册用户，也能通过邀请链接邀请尚未注册的人。

### D — 申请访问与审批

1. 新增申请入口、申请状态机、幂等和并发审批，连接现有授权能力。
2. 实现无权限入口、viewer 升级申请、本人状态与撤回、管理者待审批页。
3. 接入申请和结果通知；批准后刷新 shared 列表，在线 viewer 自动更新权限。

交付：主动分享、定向邀请、用户申请三条链路均可走通。

评论沿原 M4 后续实施，复用通知、个人频道与 outbox；本轮不提前建设评论线程、图钉及 @提及。

## 6. 验收与验证

- API 集成测试：管理能力矩阵、跨工作区隔离、有效角色合并、成员查询字段、幂等授权。
- 邀请/申请状态测试：token 过期与撤销、身份匹配、pending 唯一性、并发审批、事务失败无半成品授权或重复通知。
- room 测试：viewer 无法广播写入、降级/移除/撤销/过期在连接中生效、跨实例通知、重连后角色正确。
- 前端关键测试：协作中分享管理仍可见、按能力显示操作、继承权限提示、多标签页聚合及在线状态未知。
- 双浏览器验收：A owner、B admin、C editor、D viewer；管理员授权与管理可用；编辑同步给观看者；观看者无法写入。
- 邀请验收：注册用户直接加入、未注册用户持定向链接注册接受、错账号不能接受、撤销后无权限。
- 申请验收：无权限用户通过申请链接申请；viewer 申请编辑；管理者收到通知并审批；批准者获得权限，拒绝者收到结果；离线后重新登录通知仍在。
- 名单验收：owner、工作区继承与直接授权均展示；待邀请与 guest 不误计为授权成员；共享列表与授权结果一致。
- 回归：本地草稿、保存、图片、断网恢复、切换画布及已有 guest 分享链接。
